# GOOD/RED migration examples

Preserve the repository's version, lockfile, and compatibility contracts while migrating one owned slice at a time. **RED** is a contrast for review; use GOOD as the implementation pattern.

## Pin and lockfile ownership

### GOOD

```diff
--- a/package.json
+++ b/package.json
@@
-"packageManager": "bun@1.3.14"
+"packageManager": "bun@1.4.0"
```

```diff
--- a/bun.lock
+++ b/bun.lock
@@
+# Regenerated by Bun 1.4 after install; dependency and test checks passed.
```

### RED

```diff
--- a/package.json
+++ b/package.json
@@
-"packageManager": "bun@1.3.14"
+"packageManager": "bun@latest"
```

```diff
--- a/bun.lock
+++ b/bun.lock
@@
-... existing resolved graph ...
+(deleted to hide unresolved migration changes)
```
